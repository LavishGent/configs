Build an internal Claude Code plugin marketplace from scratch. This is a git monorepo where teams publish and share
  reusable Claude Code plugins (slash commands + skills) across an organization.

  ---

  ## What to Build

  1. Directory structure for organizing plugins by team and domain
  2. A central plugin registry (marketplace.json) auto-generated from individual plugin manifests
  3. Scripts to sync, validate, and manage the registry
  4. CI pipeline that enforces consistency and auto-fixes common mistakes
  5. Built-in slash commands for contributors to manage the marketplace

  ---

  ## Directory Structure

  {repo-root}/
  ├── .claude-plugin/
  │   └── marketplace.json              # Auto-generated central registry
  ├── product/
  │   └── {team}/
  │       └── {domain}/
  │           └── {responsibility}/     # Plugin root
  ├── enterprise/
  │   └── {plugin-name}/                # Plugin root (cross-team tools)

  │   ├── validate-manifests.js
  │   └── utils.js

  ├── tests/marketplace/
  ├── CLAUDE.md
  ├── Makefile
  ├── package.json
  └── .ci.yml

  Each plugin root contains:
  {plugin-root}/
  ├── .claude-plugin/plugin.json
  ├── commands/{verb}.md
  └── skills/{skill-name}/SKILL.md

  ## Schemas

  ### marketplace.json

  ```json
  {
    "name": "{org}-claude-marketplace",
    "owner": { "name": "{org}" },
    "metadata": { "description": "..." },
    "plugins": [
      {
        "name": "team-domain-responsibility",
        "description": "...",
        "author": { "name": "..." },
        "category": "development",
        "source": "./product/team/domain/responsibility"
      }
    ]
  }

  - Never edited manually — always regenerated by sync script
  - No top-level version field
  - Plugin entries do NOT contain version — versions live only in plugin.json
  - Plugins sorted alphabetically by name
  - Valid categories: development, testing, review, documentation, tooling, integration

  plugin.json

  {
    "name": "team-domain-responsibility",
    "version": "1.0.0",
    "description": "...",
    "author": { "name": "..." },
    "keywords": ["keyword1", "keyword2"]
  }

  - name derived from directory path: strip product/ or enterprise/, join remaining segments with -
    - product/epic/api/review → epic-api-review
    - enterprise/gitlab-mcp → gitlab-mcp
  - version must match MAJOR.MINOR.PATCH
  - category must NOT appear here — validation fails if present
  - keywords must be a non-empty array

  Command files (commands/{verb}.md)

  ---
  description: One-line description
  argument-hint: "[optional-arg]"
  allowed-tools: "Read, Grep, Glob, Bash, Write, Edit"
  ---

  Brief description.

  ## Instructions

  ### Step 1: ...
  ### Step 2: ...
  ### Step 3: Confirm with user before making changes
  ### Step 4: ...

  - Filename (minus .md) is the verb; full command = {plugin-name}:{verb}
  - $ARGUMENTS is replaced with user-provided input
  - Body is free-form markdown instructions for Claude

  Skill files (skills/{name}/SKILL.md)

  ---
  name: skill-name
  description: One-line description of knowledge coverage
  user-invocable: false
  ---

  # Skill Title

  Reference content — patterns, rules, code examples.

  - Skills = reference knowledge (what the patterns/rules are)
  - Commands = step-by-step workflows (how to do X)
  - Folder-per-skill: directory name is the skill identifier

  Scripts

  utils.js

  Shared utilities:
  - readJson(path) / writeJson(path, data) — only write if content changed
  - isSemver(str) — validates MAJOR.MINOR.PATCH
  - compareSemver(a, b) — returns -1/0/1
  - classifyVersionDelta(from, to) — returns 'patch'|'minor'|'major'|null
  - bumpPatch(version) / bumpMinor(version)
  - findPluginManifestPaths(roots) — recursively finds all .claude-plugin/plugin.json paths
  - pluginRootFromManifest(manifestPath) — strips /.claude-plugin/plugin.json
  - expectedPluginName(pluginRoot) — derives expected name from directory path
  - buildMarketplacePlugin(manifest, source, existingCategory) — projects to marketplace entry shape

  validate-manifests.js

  Validate all plugins. Optionally accept changed file list and baseline versions for CI context.

  Checks per plugin:
  1. Manifest is valid JSON
  2. name is non-empty string matching expected name from directory path
  3. version (if present) matches semver
  4. description is non-empty string
  5. author is object with non-empty name
  6. keywords is non-empty array
  7. category must NOT exist
  8. No duplicate plugin names across the marketplace
  9. New plugins: version must be 1.0.0 or omitted
  10. Changed plugins: version must increment exactly one semver step from baseline
  11. Version must never decrease

  Returns { errors: string[], versionSuggestions: Map<manifestPath, newVersion> }

  sync-marketplace.js

  1. Find all manifests under product/ and enterprise/
  2. Read CHANGED_FILES env var (comma-separated paths) to identify modified plugins
  3. For changed plugins where plugin.json itself was NOT changed: auto-bump version
    - Check MERGE_REQUEST_TITLE or equivalent: feat: prefix → minor, else → patch
  4. Write updated plugin.json files (only if changed)
  5. Rebuild marketplace.json: project each manifest to marketplace entry, preserve existing category
  6. Sort plugins alphabetically by name
  7. Write marketplace.json (only if changed)

  ---
  CI Pipeline

  Stages: test → verify → release

  Run on: MR/PR events and pushes to default branch.

  lint: ESLint + Prettier check

  test: Run unit tests with Node.js built-in test runner

  verify: Install Claude Code CLI globally, then run make verify which calls claude plugin validate on the marketplace
   root and each plugin

  mr_check (MR only): Run sync + validate. If issues found, auto-commit fixes to the MR branch and post a comment
  describing what was corrected.

  release (default branch): Use semantic-release or equivalent to version the repo and generate a changelog from
  conventional commits.

  Makefile

  verify:
        claude plugin validate .
        @for dir in $$(find product enterprise -name ".claude-plugin" -type d | sed 's|/\.claude-plugin$$||'); do \
                claude plugin validate $$dir; \
        done

  marketplace-validate:
        node scripts/marketplace/validate-manifests.js

  marketplace-sync:
        node scripts/marketplace/sync-marketplace.js

  test:
        node --test tests/marketplace/**/*.test.js

  lint:
        npx eslint . && npx prettier --check .

  format:
        npx prettier --write .

  Built-in Repo Commands (.claude/commands/)

  These are available to anyone working in this repo (not plugins — repo-level commands):

  - market:create-plugin.md — scaffold a new plugin with correct structure
  - market:add-command.md — add a command to an existing plugin
  - market:add-skill.md — add a skill to an existing plugin
  - market:check-idea.md — check for duplicate coverage before building
  - market:create-team.md — add a new team directory with first plugin

  ---
  CLAUDE.md

  Document:
  - How validation works (make verify)
  - Plugin naming convention (path → name derivation)
  - When to use product/ vs enterprise/
  - Semver rules (patch/minor/major and when each applies)
  - How to add a plugin or team
  - How to run the sync script after changes

  ---
  Key Design Principles

  1. Manifests are source of truth. marketplace.json is always derived — regenerate it, never edit it directly.
  2. CI auto-fixes common mistakes. Forgotten version bumps are committed to the branch automatically.
  3. Plugin naming is structural. The plugin name is deterministically derived from its directory path — no manual
  naming.
  4. No runtime dependencies. All scripts use Node.js built-ins only.
  5. Discovery is recursive. Find .claude-plugin/ directories anywhere under product/ and enterprise/.
  ```
